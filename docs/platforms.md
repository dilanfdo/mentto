# Android and iOS setup

Both apps come from the same code. The `android/` and `ios/` folders are **generated by
`expo prebuild` and gitignored**, so native changes go in `app.json`, `app.config.js` or a config plugin, never in
those folders.

Step-by-step release instructions are in [PLAY_STORE.md](./PLAY_STORE.md) and [ios-release.md](./ios-release.md).

## At a glance

| | Android | iOS |
|---|---|---|
| App ID | `app.nexusdigitallabs.mentto` | `app.nexusdigitallabs.mentto` |
| Store state | Live, 1.0.0 (2) | TestFlight, 1.0.0 (1) |
| Devices | Phones and tablets | iPhone only (`supportsTablet: false`) |
| Minimum OS | Android 7 (API 24), target API 36 | iOS 16.4 |
| Orientation | Portrait | Portrait |
| User-facing version | `expo.version` | `expo.version` |
| Upload number | `expo.android.versionCode` | `expo.ios.buildNumber` |
| Built with | Gradle, locally | Xcode, locally |
| Signing | Upload key from `~/.mentto-signing`, then Play App Signing | Xcode automatic signing, team `S3NGY3A2RA` |
| Payments | Google Play | App Store |
| RevenueCat key | `goog_...`, default in `src/lib/config.ts` | `appl_...`, from `.env.production.local` |
| Google client | One OAuth client per signing key, nothing compiled in | One iOS client, compiled in |
| Device backup | Android Auto Backup | iCloud Backup |

Neither platform is built on EAS. Builds are local, which is faster and leaves no signing credentials with a
third party.

## Configuration

| File | Purpose |
|---|---|
| `app.json` | Main Expo config: names, IDs, versions, permissions, plugins |
| `app.config.js` | Adds to `app.json` what depends on environment variables: the Apple team and the Google URL scheme |
| `src/lib/config.ts` | Runtime settings, read from `EXPO_PUBLIC_*` variables with safe defaults |
| `.env.example` | Documents the variables |
| `.env.local` | Local development overrides (gitignored) |
| `.env.production.local` | iOS release values (gitignored) |

| Variable | Used for |
|---|---|
| `EXPO_PUBLIC_BILLING_MODE` | `store` makes a debug build use real billing |
| `EXPO_PUBLIC_REVENUECAT_API_KEY_ANDROID` | Overrides the built-in `goog_` key |
| `EXPO_PUBLIC_REVENUECAT_API_KEY_IOS` | The `appl_` key; without it iOS Pro is unavailable |
| `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` | iOS Drive sign-in; needs a new prebuild when it changes |
| `APPLE_TEAM_ID` | Pins the Xcode project to the personal paid team |
| `MENTTO_IOS_RELEASE=1` | Set by the release script; generation fails without the team and Google client |
| `MENTTO_SIGNING_FILE` | Alternative path to the Android signing properties |

`EXPO_PUBLIC_*` values are compiled into the app, so they're public. Never put a secret there, such as a RevenueCat
`sk_` key.

## Config plugins and native modules

| Item | Platform | Job |
|---|---|---|
| `plugins/withReleaseSigning.js` | Android | Adds the upload key to the Gradle release build; falls back to the debug key if it's missing, which runs locally but can't be uploaded |
| `plugins/withAccentColor.js` | Android | Sets the theme accent, so date and time dialogs are indigo rather than teal |
| `expo-build-properties` | Android | R8 minify and resource shrinking in release |
| `modules/exact-alarms/` | Android | Local Kotlin module: checks and opens the "Alarms & reminders" setting. On iOS its functions report that nothing is needed |
| `modules/restore-key/` | Android | Local Kotlin module: saves, reads and deletes the restore key that signs a tutor back in on a new phone. See [integrations](./integrations.md#restoring-sign-in-on-a-new-phone). On iOS its functions do nothing |
| Google Sign-In plugin (from `app.config.js`) | iOS | Adds the reversed client ID as a URL scheme |
| `expo-font`, `expo-notifications`, `expo-splash-screen`, `expo-sqlite`, `expo-sharing` | Both | Fonts, notification icon, splash and native setup |

## Permissions

**Android:** `INTERNET`, `VIBRATE` and `SCHEDULE_EXACT_ALARM` in `app.json` and the template, with
`POST_NOTIFICATIONS` and `RECEIVE_BOOT_COMPLETED` from `expo-notifications`. `blockedPermissions` removes
`SYSTEM_ALERT_WINDOW` and the legacy storage permissions. There's no `AD_ID`.

**iOS:** only the notification prompt at runtime. No camera, contacts, location or tracking prompts.
`usesNonExemptEncryption: false` means no export question on each upload, because the app only uses system HTTPS.
Third-party SDKs ship privacy manifests, which are combined into the app at build time.

## Where the platforms behave differently

### Reminders

| | Android | iOS |
|---|---|---|
| Permission | Prompt on Android 13+ | Prompt |
| Exact timing | Needs "Alarms & reminders". Without it, reminders can be up to an hour late, and Today and Settings prompt for it | Always on time |
| Channels | `lessons` (high), `fees` (default) | Not applicable |
| Limit | The app's cap of 60 | 64 pending, by the OS |

### Date and time pickers

Android uses native dialogs. iOS has none, so `src/components/ui/PickerField.tsx` shows the picker inline. "Move this
lesson" opens two Android dialogs in a row, while iOS shows a form inside the lesson sheet
(`src/components/LessonSheet.tsx`).

### Paywall

`src/app/pro.tsx` varies by platform:

- **iOS:** auto-renewal terms, a Terms of Use link (Apple's standard EULA), Apple Account wording, and a manage link
  to `apps.apple.com/account/subscriptions`.
- **Android:** Google Play wording and a manage link to the Play subscriptions page.
- **Both:** Restore purchases and a Privacy Policy link.

Apple requires the renewal terms and legal links for subscriptions, so don't remove them.

### Press feedback

Android uses `android_ripple`. iOS has no ripple, so `withPressFeedback` in `src/components/ui/pressFeedback.ts` dims
pressed rows.

### Text

- **Fit-to-width:** `adjustsFontSizeToFit` collapses text to a sliver in the auto-height stat tiles on iOS, so
  `FitTitle` in `src/components/ui/Text.tsx` scales by length there and keeps the native behaviour on Android.
- **Field alignment:** a fixed line height pushes single-line `TextInput` text low on iOS, so `TextField` removes it.

### Keyboard

Android uses `softwareKeyboardLayoutMode: resize`. On both, `Screen` wraps content in a `KeyboardAvoidingView`.

### Device backups

The database is in app storage on both, so it's included in Android Auto Backup and iCloud Backup where the owner has
them on. Settings mentions the matching one. These are separate from Drive backup, and Google or Apple handles them.

## Android builds

Needs Android Studio's JDK and the Android SDK.

```bash
rm -rf android
CI=1 npx expo prebuild --platform android --no-install
echo "sdk.dir=$ANDROID_HOME" > android/local.properties
(cd android && JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew bundleRelease assembleRelease)
```

- **Upload:** `android/app/build/outputs/bundle/release/app-release.aab`.
- **Signing:** `~/.mentto-signing/keystore.properties` names the keystore and passwords, kept outside the repo. Play
  re-signs with its own App Signing key, which is why Google has separate OAuth clients for the Play and upload keys.
- **Checks before upload:** see [PLAY_STORE.md, Part 4](./PLAY_STORE.md).
- **Archive:** keep release files in `~/Desktop/Mentto-Releases/<version>-code<N>/`.
- **Careful:** `gradlew installDebug` targets every attached device, so with a phone connected, install with
  `adb -s <device>` instead.

## iOS builds

Needs Xcode and CocoaPods.

### Simulator (no signing)

```bash
CI=1 npx expo prebuild --platform ios --clean
cd ios && xcodebuild -workspace Mentto.xcworkspace -scheme Mentto -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=NO
```

Then install the `.app` from `ios/build/Build/Products/` with `xcrun simctl install`, and start Metro with
`npx expo start`.

- **Don't start Metro with `CI=1`.** It turns off file watching, so edits don't appear and a working fix looks broken.
- **Expected in unsigned builds:** an `expo-notifications` keychain error banner, because there are no entitlements.
  Signed builds don't have it.
- **Debug builds simulate Pro** unless `EXPO_PUBLIC_BILLING_MODE=store` is set.

### Release

```bash
scripts/ios-release-prepare.sh
open ios/Mentto.xcworkspace
```

The script reads `.env.production.local`, regenerates `ios/`, and checks the team, the keys and the URL scheme. Archive
from Xcode with **Any iOS Device (arm64)** selected, then upload from the Organizer. Details are in
[ios-release.md](./ios-release.md).

**Signing safety:** this Mac's Xcode also knows a free Personal Team and a LetsBridge team, and the keychain holds a
LetsBridge certificate. Mentto must only be signed by team `S3NGY3A2RA`, which is why the team is pinned and the script
refuses any other. Never select another team.

## Versioning

- User-visible release: bump `expo.version`, shared by both platforms.
- Every Android upload: bump `expo.android.versionCode`.
- Every iOS upload: bump `expo.ios.buildNumber`.
